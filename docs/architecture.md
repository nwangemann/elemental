# Architecture

## Layers

- `src/core`: pure TypeScript. Maths, layout, data shaping, rules. No React, no three, no DOM, so everything here is unit-tested in Node.
- `src/scene`: React Three Fiber components (see [ADR 2](adr/0002-scene-rendering.md)). Per-frame work happens in `useFrame` and mutates refs; it never sets React state.
- `src/state`: the app store (zustand, [ADR 4](adr/0004-app-state.md)), shared by the scene and the DOM interface. `activeTile` is the tile under the character (number, name and symbol), or null; the scene writes it only when that changes. `flight` is the latest fly-to request (`flyTo(number)`), from the explorer or a deep link. `panelClosed` is true while the player has closed the panel with Esc on the current tile; entering another tile resets it. `lastTile` is the last tile stood on (kept while off the table) and `offTable` is true while the character is on the ground (ADR 0009); both change only on change. `returnSeq` counts return requests (`requestReturn()`). `walk` is the latest walk request (`walkTo(number)`, Combine's Show me), carried out like a return. `lens` is how the table is read (`core/lens.ts`, [ADR 11](adr/0011-lenses.md)): the property the height and colour lenses show (`setLensHeight`, `setLensColour`), the temperature lens's kelvin or null (`setLensTemperature`), the discovery lens's year or null (`setLensYear`, `ANTIQUITY` for the stop) and the explorer's filters (`setLensFilters`), written only when the player changes them. `combine` is combine mode's state ([ADR 20](adr/0020-combine-mode.md)): `open`, and `carry`, the atoms carried as symbols in the order picked up (`core/carry.ts`). `pickUpAtom(symbol)` opens Combine and adds one atom if the carry limit allows, and otherwise records `refused` (the symbol and `canAdd`'s reason) for the tray to explain; `dropLastAtom`, `setCarry` and `setCombineOpen` do the rest, and any change to the carry clears `refused`.
- `src/ui`: DOM interface. The element panel (`ElementPanel.tsx`), a screen-reader status that announces the tile under the character (`TileStatus.tsx`, "Standing on Hydrogen"), the explorer (`Explorer.tsx`), the key map overlay (`KeyHelp.tsx`), the plain-text element list (`ElementList.tsx`), the return key and button (`BackToTable.tsx`), combine mode's keys (`CombineKeys.tsx`), combine mode's tray (`CombineTray.tsx`) and the dev-only tuning panel.
- `src/data`: generated element data (`elements.json`) and combine mode's compound set (`compounds.json`) and its atom colours, molecule shapes and crystal chunks (`compound-shapes.json`), committed. Built by `scripts/build-elements.ts` and `scripts/build-compounds.ts`; see [data sources](data-sources.md).
- `src/assets`: the tile label atlas (`label-atlas.png`, a greyscale signed distance field, and `label-atlas.json`, its metrics), committed. Built by `npm run atlas` (`scripts/build-label-atlas.ts`): Chromium from the Playwright dev dependency rasterises each glyph the labels use from Inter Bold at 4× supersampling, `scripts/sdf.ts` turns coverage into an exact distance field, and `scripts/png.ts` writes the PNG. Re-run it when the font or the element symbols change; a unit test fails if a label needs a glyph the atlas lacks.

## Core modules

- `damp.ts`: frame-rate independent smoothing. `damp` is first-order exponential smoothing (movement, zoom); `stepSpring` is an exact critically damped spring with velocity, which eases in and out and never overshoots a still target (camera follow).
- `camera.ts`: the third-person camera as pure maths. A focus point follows the character on two springs, aimed `lookAhead` seconds along its velocity so the view leads the walk. That aim is clamped to bounds the rig passes in (the table's footprint plus `focusMargin`), so the view stops at the table's edge while the character walks on into the margin and the table stays in frame. The camera sits behind and above the focus at `pitch` and a zoom distance that eases toward a target, clamped between `minDistance` and `maxDistance`; zoom works in log steps (`zoomBy`, one key press or 100 px of wheel) or by a pinch factor (`zoomByFactor`). Its heading is fixed (looking toward −z), so keyboard directions stay screen-relative. The establishing shot holds the overview pose (`CONFIG.camera.position` and `target`) for `introDelay`, then blends into the follow pose over `introDuration` with a smootherstep curve; `skipIntro` ends it at once. `followHeight` eases the focus height toward the figure's feet on the same spring frequency, so the view climbs a height lens landscape with it and hops are smoothed out; `focusHeight` is measured from the feet. `sheetLift` gives how far to shift the image up so the focus sits mid-way in the part of the view a bottom sheet leaves visible (half the covered height), and `stepLift` eases toward it at `liftRate` (or jumps, under reduced motion).
- `elements/categories.ts`: the fixed value lists (the ten families that drive tile colours and themes, states, blocks), free of zod so the app can import them.
- `elements/schema.ts`: the zod schema and the `Element` type. Only the data script and tests run it; the app imports its types, so zod is not in the app bundle.
- `elements/position.ts`: period, group and block from the atomic number.
- `elements/normalize.ts`: turns PubChem's table and Wikidata's SPARQL rows into validated elements, dating fluorine, aluminium and calcium by isolation (`DISCOVERY_OVERRIDES`, [ADR 19](adr/0019-discovery-timeline.md)). Used by the build script and its tests.
- `elements/index.ts`: `ELEMENTS`, the committed dataset, and lookups. This is what the app imports.
- `compounds/source.ts`: combine mode's curated compound list ([ADR 20](adr/0020-combine-mode.md)), in everyday order: name, display formula, kind (molecule, lattice, alloy, lone atom), bond chip, contexts, starters, leads-to and the card copy. Also `CARRY_LIMIT` (5 elements, 24 atoms). Free of zod.
- `compounds/normalize.ts`: `parseFormula` (subscripts, groups, PubChem's Hill formulas), and `buildCompounds`, which merges the list with PubChem's CID and formula, fails if a display formula disagrees with PubChem's, and derives counts, atoms, carryable and isomers. Used by the build script and its tests.
- `compounds/cif.ts`: reads a CIF's cell, symmetry operations and atom sites (`parseCif`, `parseOp`), fills the unit cell (`fillCell`, keeping a share of partly filled sites), and cuts a chunk around one atom with sticks for listed element pairs (`cutChunk`, `chunkBonds`).
- `compounds/shapes.ts`: ball-and-stick shapes. `bakeConformer` turns a PubChem 3D record into centred atoms (Å, 0.01 rounding) and 0-based bonds; `HAND_SHAPES` covers the two molecules PubChem has no conformer for; `buildCrystal` cuts a lattice chunk from its COD cell after checking the cell holds whole formula units; `HAND_CRYSTALS` builds bleach, steel and bronze; `buildShapes` checks each shape's atoms against its formula and that every element has a CPK colour.
- `compounds/contexts.ts`: what the body, dry air and the continental crust are made of by mass, from cited tables (`BODY_KG`, `AIR_PPMV`, `CRUST_PPM`); `massSharesOfGases` turns air's volume shares into element mass shares; `contextShares(context)` gives each element's share, largest first, or null for the kitchen.
- `compounds/index.ts`: `COMPOUNDS`, the committed set. Only combine's lazy chunk should import it.
- `layout.ts`: where each tile sits. An 18 × 10 grid (groups as columns, periods as rows; the two f-block rows sit under groups 3–16 after one empty row), centred on the origin of the x–z ground plane. Converts world ↔ grid and finds the tile under a point in O(1) without allocating. The lookup takes the current tile for hysteresis: a tile is kept until the character is `LAYOUT.hysteresis` past its edge, which is wider than the gap, so walking along a boundary does not flicker. Tile size, gap and margin live in `LAYOUT`.
- `labelLayout.ts`: tile label layout from the baked glyph atlas (ADR 0013). `layoutText` places one quad per character from the atlas metrics (advances, kerning, the font's line box), anchored the way the labels need: symbols centred, numbers from the top-left corner. `labelInstances` turns a list of labels into per-glyph typed arrays (tile, world rectangle on the ground, UVs) for the scene's instanced label mesh.

- `config.ts`: visual and feel parameters (tile height, resting material and theme strength, label sizes, camera). `CONFIG_DEFAULTS` holds the shipped values and `CONFIG_RANGES` the slider bounds. The app reads `CONFIG`, a mutable copy; `setConfig` changes one value, bumps a version and notifies subscribers. Per-frame code reads `CONFIG` every frame and needs no subscription. Objects built once from it (tile geometry, the label batch) are remounted by `Scene` when the version changes.
- `carry.ts`: what combine mode carries ([ADR 20](adr/0020-combine-mode.md)), as a list of symbols in the order picked up, so Backspace drops the last. `CARRY_LIMIT` (5 elements, 24 atoms), `carriedCounts` (in first-picked order), `atomsIn`, `canAdd` (ok, too many elements or too many atoms), `fitsCarry`, and the edits: `pickUp` (returns the same carry when the limit refuses), `dropLast`, `dropOne` (a stepper's −) and `withCounts` (Fill in, keeping carried elements first). Free of compound data, so the shell's store can use it.
- `forming.ts`: combine mode's forming. `pickFormed` chooses the compound shown (the tray's isomer pick, else the most everyday; a lone atom forms nothing). `assignAtoms` gives each carried orb an atom of its element in the baked shape, nearest the centre first, so a lattice grows outward from what was carried; `growDelays` staggers the uncarried atoms by distance. `fitScale` fits the shape inside `formRadius` (capped at `formMaxScale` per ångström). `formAtoms` writes each atom's position, radius and progress for a time and spin (`springEase`: a quick rise with about 8 % overshoot; in place at once with reduced motion), `formSticks` one cylinder per bond order, side by side, thinned until both atoms arrive. `arcPoints` and `arcPhase` give the table arcs between neighbouring elements' tiles and how much of them shows. `FormClock` (`stepFormClock`) restarts on a new compound and tells the pacer while anything animates.
- `orbs.ts`: where carried atoms float. `orbSlots` lays out one stack per element (columns of `orbRows`) on a shallow curve behind the figure, in its frame; `OrbFollow` with `stepOrbFollow` eases the group after the figure's position and heading (height twice as fast) and says while it is still `moving`; `snapOrbFollow` puts it on the figure while hidden.
- `gait.ts`: the character's procedural motion. `stepGait` advances time, the walk phase (one cycle per `strideLength` travelled, so feet do not slide at any speed) and a walk blend that follows speed; `poseOf` turns that into body bob, squash and stretch (volume kept), foot swing and lift, and arm swing, written into a reused object. Idle breathing fades out as the walk fades in.
- `input.ts`: keyboard movement as data. `KEY_MAP` maps `KeyboardEvent.code` (physical keys, so WASD works on any layout) to actions: WASD and the arrows both move, either Shift walks slowly. `applyKey` records presses into a set of held codes, and `moveIntent` turns them into a normalised x–z direction (a `MoveIntent` may be shorter than 1, from the joystick or a slowing approach, and its length scales speed) (forward is −z, away from the camera; opposite keys cancel). `ZOOM_KEYS` maps the typed `+`/`=` to zoom in and `-`/`_` to zoom out; these go by `KeyboardEvent.key`, since the characters sit on different physical keys across layouts.
- `steering.ts`: pointer and touch movement. `setWalkTarget` turns a point on the table into a walk target, snapped to the centre of the tile under it (or kept as is over a gap). `stickFromOffset` maps the joystick knob's screen offset to an analog x–z vector (screen up is −z, matching the fixed camera; a dead zone, then linear to full at `stickRadius`). A target set with `climb` (keyboard steps, the return) may walk over cliffs; a tap's may not. `steer` merges the sources into the frame's `MoveIntent`: held keys win and cancel any walk target, then a deflected joystick, then the target, steered toward in a straight line and slowed linearly inside `slowRadius` until it is reached at `arriveRadius`. `isTap` tells a tap or click (short and still) from a drag. `FloatingStick` (`floatPress`, `floatMove`, `floatRelease`, `floatCancel`) is the phone joystick's state: a touch is a candidate until it drifts past `TAP_MAX_PX`, then becomes a stick centred where it landed, deflected through `stickFromOffset`; a second finger cancels it. Parameters live in `CONFIG.character`.
- `tapMarker.ts`: the marker a tap leaves on its walk target. `placeTapMarker` starts it on the target just set (tile index, or −1 for a gap or ground point); `stepTapMarker` ages it and ends it once that target is no longer the active one (arrival, keys, joystick, a step key, another tap, a fly-to); `tapMarkerLook` gives the pulse: from 1.6× size and full opacity, eased over `markerPulse` seconds to rest size and `markerOpacity` (size fixed under reduced motion). Parameters live in `CONFIG.tiles`.
- `controller.ts`: the kinematic character controller. `stepController` eases velocity toward the intent with `damp` (separate rates for accelerating and stopping), softens the edge of its bounds (in a band `edgeBand` wide inside each limit the outward speed allowed falls to zero and a push of up to `edgePush` eases the body back inside), integrates position, clamps it to the bounds as a guarantee and zeroes velocity against them, turns the heading toward the travel direction the short way round, and leans into turns in proportion to turn rate × speed, capped. Allocation-free; parameters live in `CONFIG.character`.
- `palette.ts`: the family colours, label ink, ground and sky, the character's body and eyes, the panel's surface and text, the colour lens's ramp (`COLOUR_RAMP`, the light half of viridis) and no-data grey, linear-light conversion (`linearRgb`) and WCAG contrast helpers. Tests check AA contrast for label ink on every family colour, that the ground stands off the sky (at least 1.4:1) and that every family colour stands out on the ground (at least 3:1).
- `themes.ts`: each element family's look as data (ADR 0006). A `Theme` holds the tile's base colour (from `palette.ts`), the `awake` surface it wakes into (roughness, metalness, glow strength and colour, and how deeply the glow pulses) and the interface's accent tokens. `accentTokens(category)` gives the DOM panel its accent and the ink for text on it, so the panel and the tile come from one entry. `surfaceAt` blends a tile's surface from a shared resting look (`CONFIG.tiles.roughness`/`metalness`, leaning `restMix` toward the family) to the awake look by activation level, writing into an instance buffer without allocating. Tests check every family has a theme, values stay in range, and accents keep AA contrast on the panel.
- `activation.ts`: which tile the character stands on and how far each tile is through entering or leaving. `stepActivation` finds the current tile with `tileAtPoint` (with hysteresis); given `standingOn` from `ledge.ts`, there is no current tile unless the character stands on a tile top, and just past a tile's edge the supporting tile counts. It ramps it linearly toward 1 and every other tile toward 0 over `CONFIG.tiles.activateDuration` (0.25 s), and reports whether the current tile changed. A `dirty` flag per tile (and `anyDirty`) tells renderers which tiles moved this frame. `easeLevel` is the smoothstep the renderers apply; `lift` holds each tile's height-lens lift; `placeLift` sets it at once and `stepActivationLift` eases it (after `stepActivation`, which clears `dirty`); `phaseLift` holds the temperature lens's gas float, written by `stepActivationPhase` the same way, and `eraSink` the discovery lens's sink, written by `stepActivationEra`. `tileTop` is a tile's top height: resting height, lens and gas lifts, less the sink, plus the eased rise (never below a small floor), so everything that reads it (tiles, labels, the tap marker, the figure's footing) follows the lens. Allocation-free.
- `explorer.ts`: the explorer's logic (ADR 0007). `explore` filters elements by family, state, block, period and group, matches a query in tiers (exact number, symbol or name; prefix; contains; then letters in order, from three letters) and orders each tier by the chosen sort (atomic number, name, mass, discovery year with antiquity first, density, electronegativity, melting point), either direction, unknowns last. `sortValueLabel` formats the sorted value with its unit. `deepLink` and `parseDeepLink` write and read `#/Au` (also accepting `#/au`, `#/79` and `#/gold`), with an optional query for the lenses (`?lens=density` for height, `?colour=meltingPoint` for colour, `?t=` for temperature, `?year=` for the discovery year, or any mix) that `parseDeepLink` ignores.
- `lens.ts`: lenses, ways of reading the whole table at once ([ADR 11](adr/0011-lenses.md)). `LENS_KEYS` are the numeric properties a lens can show (mass, density, electronegativity, melting and boiling point, radius, ionization energy, discovery year), each with a default scale in `LENS_SCALES` (density is log, the rest linear). `lensLevels` maps a property to a level in [0, 1] per tile over the range of known values, with `NO_DATA` (−1) for unknowns; antiquity counts as the earliest discovery. `filterDim` turns the explorer's filters into a dim target per tile (1 = excluded); a `DimLayer` is a second source of dim targets (combine mode's suggestions), merged as the stronger of the two by `mergeDim` and picked up once per change by `takeDimLayer`; `stepDim` fades levels toward their targets at a constant rate (0 s snaps), and `shownDim` lifts the dim as a tile wakes, so the tile underfoot keeps its colour. For the height lens, `liftTargets` turns levels into an extra height per tile (`CONFIG.tiles.lensFloor` up to `lensHeight`, 0 for no data or no lens), and a `LiftEase` (`retargetLift`, `stepLift`) moves the whole table together from its old heights to the new over `lensDuration`, smoothstepped, marking moved tiles dirty. For the colour lens, `rampColour` blends the ramp at a level in linear light (no-data grey for `NO_DATA`), `colourTargets` gives each tile its target colour (ramp with a lens on, family colour with it off), a `TintEase` (`createTintEase`, `retargetTint` from wherever the colours are mid-ease, `stepTint`) moves the whole table between colourings, smoothstepped, and `tintAt` gives a tile's drawn colour: its eased lens colour blended back to its family colour by how awake it is and `lensLegend` gives the legend's lowest, middle and highest values with units, the log-scale flag and the no-data count. `LENS_LABELS`, `lensValueLabel` and `formatLensValue` (value with unit), `cycleLens` (the H key's order) and `lensFromHash` (`?lens=` or `?colour=` in a deep link) serve the interface. Allocation-free when given buffers.
- `temperature.ts`: the temperature lens ([ADR 18](adr/0018-temperature-lens.md)). `phaseAt(e, kelvin)` gives solid, liquid, gas or unknown at 1 atm from the melting and boiling points (sublimation where the boiling point is at or below the melting point; helium never solid; unknown with no melting point, or above it with no boiling point). `phaseTargets` writes one `PHASE_CODE` per tile and `phaseCounts` counts each state. `kelvinAt` and `positionOf` map the slider's 0–1 track to 0–6,000 K on a log scale with an offset, and `snapKelvin` snaps to `DETENTS` (room, body, water boils); `sliderKelvin` is what a slider position sets (snapped for pointer drags, not for keyboard steps, which are smaller than the snap window; otherwise rounded to the readout's precision) and `detentAt` names a detent. `phaseFact` is the panel's "At 310 K: Liquid" row (`shortKelvin` for the label) and `phaseSummary` the counts in words. `temperatureFromHash` and `temperatureParam` read and write `?t=` in kelvin. For the scene, a `PhaseEase` (`createPhaseEase` resting at a temperature, `retargetPhase`, `stepPhase`) moves each tile's shown phase (0 solid → 1 liquid → 2 gas; unknown tiles stay at 0) at one state per `CONFIG.tiles.phaseDuration`, with an `unknown` level (0–1) beside it, and `gasAmount` turns a shown phase into the smoothstepped share of gas that floats and fades a tile.
- `trayText.ts`: the Combine tray's words ([ADR 20](adr/0020-combine-mode.md)). `traySummary` is the live region's text: a carry-limit refusal if any (`refusalLine`), then "Carrying H 2." (`carryLine`, symbol and count in first-picked order), then `leadsLine`: what forms now ("Makes water.", every isomer) followed by the nearest bigger compound when one only needs atoms added, or else the nearest compound with the atoms to add or drop, after "Nothing in the set forms from just these." when no compound holds every carried atom. With nothing carried it offers the starters ("Try water, table salt or carbon dioxide."). Counts are words up to ten (`countWord`). `nearMissLine` is one row of the tray's nearest list ("Water — 1 fewer C, 1 more O"), and `ratioLine` teaches a Fill in ratio ("Glucose is C₆H₁₂O₆: 1 carbon, 2 hydrogen, 1 oxygen, six times over.").
- `compoundCard.ts`: the compound card's parts ([ADR 20](adr/0020-combine-mode.md)): `BOND_LABELS` (the bond chip's words), `madeOf` (element chips with tile numbers, in formula order) and `leadsTo` (Leads to items, linked when one names a compound in the set). Recently made: `addRecent` (newest first, no duplicates, at most `RECENT_LIMIT`, 8) and `parseRecent`, which reads stored text and drops anything unknown or malformed.
- `tour.ts`: Show me's route. `tourStops` gives each element of a compound in formula order with the atoms to pick up there (exact counts, one of each for an alloy or a compound too big to carry), and `tourMove` says whether the figure walks (within `WALK_REACH`, about four tiles), flies (further, or always with reduced motion) or is already there.
- `combine.ts`: combine mode's matching ([ADR 20](adr/0020-combine-mode.md)), over a carry given as a symbol → count map and the compound list passed in. `exactMatches` is what forms now: exact counts for compounds, the set of elements for alloys, every isomer of a formula (ethanol and dimethyl ether), in everyday order; `leftover` is what stays carried after a compound forms. `distance` gives the atoms to add and to drop; `nearest` sorts the carryable compounds that share an element with the carry by atoms to drop, then atoms to add, then everyday rank, for the tray, and `nothingForms` says when no compound holds every carried atom. `wrongAmounts` finds compounds made of exactly the carried elements in other numbers, with the counts Fill in sets and the ratio (`unit`, `times`: glucose is C₁H₂O₁ six times over). `suggestionWeights` writes one 0–1 weight per tile for the table's dimming: each compound the carry is still part of adds its everyday weight to every element it still needs, and a tile the carry limit stops (`canAdd`, `fitsCarry`: 5 elements, 24 atoms) gets 0. `suggestionDim` turns weights into dim targets: 0 for the strongest suggestion, up to `CONFIG.combine.suggestDim` for the faintest, 1 where picking the element up leads nowhere. `fillIn` is the tray's Fill in offer: the closest `wrongAmounts` compound of two or more elements, only while nothing forms.
- `discovery.ts`: the discovery timeline ([ADR 19](adr/0019-discovery-timeline.md)). `knownBy(e, year)` says whether an element was known in a year (antiquity elements always; `ANTIQUITY`, −Infinity, is the slider's first stop). `discoveryTargets` writes 1 per undiscovered tile and 0 otherwise (all 0 with the lens off), `discoveryCounts` gives known and to come (`discoverySummary` in words), and `discoveredIn(elements, from, to)` lists what was found between two years, by year. `yearAt` and `positionOfYear` map the slider's track: the Antiquity stop at 0, a compressed 1650–1750, then linear to 2010 (`YEAR_MAX`, the latest discovery); `sliderYear` snaps to `YEAR_DETENTS` (Antiquity, Lavoisier's list 1789, Mendeleev's table 1869, Today) for pointer drags only, and `yearLabel` writes a year or "Antiquity". `yearFromHash` and `yearParam` read and write `?year=` (`?year=antiquity` for the stop). `EraEase` is the lens as the scene draws it: `createEraEase` rests at a year, `retargetEra` points it at another, and `stepEra` moves each tile linearly between 0 (known) and 1 (undiscovered) over `CONFIG.tiles.eraDuration`. `eraSink` shapes a level into a share of `CONFIG.tiles.eraDepth`, smoothstepped; a tile rising from more than `SETTLE_WINDOW` down (`rising`) overshoots its place by up to `CONFIG.tiles.eraSettle` of the depth over the end of its rise and drops back. `eraGrey` shapes the grey, without the settle. In words: `eraFact` is the panel's line, `discoveryNews(from, to)` what an announcement says changed (latest first going forward, "and N more" past six) and `latestDiscoveries` the latest year with a discovery up to a year, with its finds. `playStart` and `nextDecade` time the Play sweep.
- `tileStep.ts`: keyboard stepping from tile to tile (ADR 0008). `STEP_KEYS` maps I, J, K and L (by code) to up, left, down and right. `stepTile` finds the next tile in a direction, skipping gaps and empty cells, through the gap row into and out of the f-block, and to the nearest tile of the next row when a column runs out; null at the edge. `nearestTile` gives a starting tile when the character stands between tiles. `RETURN_KEYS` (R and Home, by code) and `isReturnCode` are the keys that walk back to the table. `NUMBER_STEP_KEYS` maps `[` and `]` (by `key`, so any layout) to -1 and +1, and `stepNumber` steps by atomic number, clamped to 1–118.
- `boundary.ts`: what the character stands on (ADR 0009). Tiles are low platforms on open ground. `surfaceAt` gives the atomic number of the tile supporting a body centred at a point, or `GROUND` (0): a tile supports the centre up to `BOUNDARY.support` (0.1) past its edge, which bridges the 0.15 gaps between neighbours, so only real empty space (the d-block notch, the gap row, the corners beside the f-block, the margin outside) is ground. O(1), allocation-free. `groundHeightAt` is the resting height there (tile height or 0). `outerBounds` is the walkable area for a body: the table's footprint plus `BOUNDARY.margin` (1.5) of ground on every side. The character's height uses `surfaceAt`, and the controller is bounded by `outerBounds`, so the figure can walk off any edge onto the ground and out to the margin's soft limit.
- `ledge.ts`: the character's height and the moves between tiles and ground (ADR 0009, ADR 0014). Standing, the feet follow the surface with `damp` (`standRate`), so a rising tile is ridden and a tile-to-tile step up to `stepGlide` dips or rises gently. Leaving a tile for the ground, or for a tile more than `stepGlide` lower, starts a fall under `gravity`; moving from the ground onto a tile, or onto a tile more than `stepGlide` higher (walking, a walk target or a fly-to), starts a hop: a straight rise plus a parabolic arc ending on the tile top. Steps up to `hopStep` get an apex of `hopHeight` over `hopDuration`; taller ones scale the apex with the step and the length with its square root (`hopScale`). A hop that moves off onto something lower turns into a fall, and a fall that reaches a surface above the feet turns into a hop. Landing sets a body squash (`landSquash`) that recovers at `squashRecover`. `standingOn` is the tile under the feet only while standing on top, `GROUND` otherwise; `isAirborne` is true while falling or hopping. Parameters live in `CONFIG.character`; allocation-free.
- `climb.ts`: walking a height lens landscape (ADR 0014). `isCliff` says whether the surface at a point rises more than `climbLimit` above a reference height. `blockCliffs` undoes the part of a frame's move that walks into a cliff, per axis (so the body slides along the face), probing the body radius less `BOUNDARY.support` ahead of the centre, and zeroes that axis's velocity. `pickSurface` finds where a ray first meets the table: the nearest tile box at its drawn height (top or side), else the ground plane; it loops over the 118 tiles and is meant for taps. Pure, allocation-free apart from `pickSurface`'s small per-call range.
- `elementFacts.ts`: the element panel's text. `overviewFacts` and `propertyFacts` turn an element into labelled rows with units (temperatures in K with °C alongside, gas densities in g/L, signed oxidation states, superscript electron counts); missing values read "Unknown" and predicted ones carry a note. `CATEGORY_LABELS` names the families.
- `elementRanks.ts`: panel depth. `rankFacts` lists up to three places an element stands out: a top-three rank in the whole table ("3rd densest of all elements"), else leading its period, else its group (a period or group needs three known values to count), over density, melting and boiling points, electronegativity, atomic radius and ionization energy. `comparison` sets an element against another by the property with the largest ratio ("3.5× heavier"; temperatures in kelvin), or says nothing below 1.1×.
- `atom.ts`: the atom tab's model. `parseConfiguration` reads a stored electron configuration (noble-gas cores expanded, subshells in any order, a `(calculated)` note dropped; anything else throws) into subshells ordered by n then l; `shellsOf` groups them into shells 1 … n with electron counts. `fillingConfiguration` is the Madelung (n + l, then n) filling for a number of electrons, and `atomOf` compares the two: `breaksFillingRule` and the `differences` per subshell (Cr: 3d 5 for 4, 4s 1 for 2). `valenceShell` is the outermost occupied shell. The stored configuration is what gets drawn; the filling order is only the reference. In the dataset 19 elements break the rule (Cr, Cu, Nb, Mo, Ru, Rh, Pd, Ag, La, Ce, Gd, Pt, Au, Ac, Th, Pa, U, Np, Cm); Lr is stored as the predicted `[Rn]7s2 5f14 6d1`, so it does not. `atomSummary` is the diagram's screen-reader text ("2, 8, 13, 1 electrons; outer shell 1") and `fillingNote` the exception note's parts (what the atom has and what the rule predicts, only the subshells that differ). `electronAngles` places a ring's electrons evenly while keeping the top clear for its count label: when even spacing would put an electron under the label (32 electrons on a small ring), they spread over the rest of the ring instead.
- `frame-stats.ts`: rolling mean and percentile of frame times, allocation-free on push.
- `quality.ts`: adaptive resolution (ADR 0010). `stepQuality` averages frame intervals over one-second windows after a warm-up and steps the pixel ratio by 0.25 between `minDpr` 0.75 and the display's own ratio (capped at 2): down below about 45 fps, up above about 57 fps. Intervals over 250 ms are pauses. After three changes of direction it settles on the lower ratio. Returns true only when the ratio changes; allocation-free.
- `pacer.ts`: idle frame pacing (ADR 0016). `stepPacer` takes each frame's interval and whether anything moved, and returns how long to wait before the next frame: 0 while busy, about `1000 / idleFps` ms after `settle` still seconds, less half the display's frame interval (learned from full-rate frames). `wakePacer` resets the stillness; `paced` marks a frame that followed an idle wait. `poseMoved` compares the camera's position and rotation with their last copy. Parameters live in `CONFIG.pacing`.

## Scene

`App.tsx` loads the scene with `React.lazy`, so three, React Three Fiber, the label atlas and the element data arrive as a separate chunk after the DOM shell has painted; a "Loading the table…" status shows meanwhile (ADR 0003).

- `Scene.tsx`: the canvas (its wrapper is the scene's one focus stop: `role="application"`, a label naming the keys, the tile status as its description, a focus ring), background and fog, a hemisphere and a directional light, and the ground: a low plinth (one box mesh) covering exactly the walkable area, the table plus `BOUNDARY.margin`, so the outer limit shows as the plinth's edge with the sky beyond. The ground colour is lighter than the sky so the area reads as ground, not void.
- `TileActivator.tsx`: steps `core/activation.ts` with the character's position each frame, after the character moves (priority −0.5) and before anything draws, and writes `activeTile` to the store only when the tile changes. It passes `standingOn` from the character's ledge state, so a tile wakes only once the character is on top of it: not while it hops up, and not after it drops to the ground beside it. It also writes `offTable` (standing on `GROUND`, including mid-fall or mid-hop) when that changes. Renders nothing.
- `HeightLens.tsx`: the height lens. Right after the activation step (priority −0.25) it eases `activation.lift` toward the store's `lens.height` over `CONFIG.tiles.lensDuration` (at once with reduced motion). A deep link's `?lens=` is put in the store as the scene chunk loads, and the lens present at mount starts in place. Tiles skip frustum culling, since raised tiles outgrow the bounds computed at mount. Renders nothing.
- `ColourLens.tsx` and `sceneTint.ts`: the colour lens. `sceneTint.ts` puts a deep link's `?colour=` in the store as the scene chunk loads and builds the `TintEase` that `Scene` owns, resting at the lens present at mount. `ColourLens` retargets it when the store's `lens.colour` changes and steps it at the height lens's priority over `CONFIG.tiles.tintDuration` (0.4 s; at once with reduced motion). Renders nothing.
- `DiscoveryLens.tsx` and `sceneEra.ts`: the discovery lens, built like the temperature lens. `sceneEra.ts` puts a deep link's `?year=` in the store as the scene chunk loads and builds the `EraEase` that `Scene` owns, resting at that year (sink placed before tiles first draw). `DiscoveryLens` retargets it when `lens.year` changes, steps it at the height lens's priority (at once and without the settle under reduced motion) and writes the sink into `activation.eraSink`. Renders nothing.
- `TemperatureLens.tsx` and `scenePhase.ts`: the temperature lens. `scenePhase.ts` puts a deep link's `?t=` in the store as the scene chunk loads and builds the `PhaseEase` that `Scene` owns, resting at the temperature present at mount (its gas lift placed before tiles first draw). `TemperatureLens` retargets it when the store's `lens.temperature` changes, steps it at the height lens's priority (0.4 s per change of state; at once with reduced motion) and writes gas tiles' float (`CONFIG.tiles.gasLift`) into `activation.phaseLift`, so labels, the tap marker and the figure's footing follow through `tileTop`. Renders nothing.
- `Tiles.tsx`: all 118 tiles as one `InstancedMesh` (one draw call), positioned from `TILES`, coloured from each family's theme, and given its surface per instance with `surfaceAt`, so a tile's material fades into its family's awake look as it activates. An active tile rises by `CONFIG.tiles.rise`, stretching up from the ground so no gap opens beneath it; only tiles marked dirty are rewritten. Metals reflect a procedural studio environment (three's `RoomEnvironment`, prefiltered once at mount; nothing is downloaded), set on this material only. Tiles the explorer's filters exclude fade to a dim grey (`aDim`, from `core/lens.ts`) over `CONFIG.tiles.dimDuration`, at once with reduced motion; the attribute is rewritten only while a fade runs or a tile changes. While carrying in combine mode, tiles that lead nowhere dim the same way, and weak suggestions partly (the `suggest` layer, written by `Suggestions.tsx`). Instance colours come from the colour lens (`tintAt`): every tile while the tint eases, otherwise only tiles whose activation changed, so the tile underfoot blends back to its family colour as it wakes and the filters' dim still applies on top. The temperature lens fills `aPhase` (rewritten only while its ease moves) and dims tiles whose state is unknown by `CONFIG.tiles.unknownDim` of the filters' dim, and the discovery lens greys undiscovered tiles by `CONFIG.tiles.eraDim` of it; the strongest dim wins, and the tile underfoot keeps its colour.
- `tileMaterial.ts`: the tiles' material, a `MeshStandardMaterial` patched in `onBeforeCompile` to read roughness, metalness and glow from per-instance attributes (`aSurface`, `aGlowColor`) and to breathe the glow over time. The environment adds reflections only (its diffuse light is dropped), so family colours keep their tone. `aDim` greys and darkens a tile by `dimStrength` and fades its glow. `aPhase` makes gas tiles see-through by a screen door: a 4×4 ordered dither in screen space discards up to `gasFade` of their pixels, so they stay opaque, in the same draw call, with nothing to sort. Liquid tiles (`aPhase` near 1) ripple: rings from the centre of the top face plus a slower cross wave tilt its normal by up to `ripple` at `rippleSpeed`; shading only, so labels and footing are unchanged, and off with reduced motion. Glow scale, pulse rate, reflection strength, dim strength, gas fade and ripple are live `CONFIG.tiles` values.
- `TileRings.tsx`: a square highlight ring on the ground around each active tile, one `InstancedMesh` (one draw call). It grows out from under the tile as the tile activates and shrinks back as it leaves; at rest it is scaled to zero, so the mesh is not frustum-culled.
- `Labels.tsx`: each tile's symbol and atomic number, drawn from a baked signed-distance-field atlas (`src/assets/label-atlas.png` and `.json`, ADR 0013) as one instanced quad per glyph, in one draw call. Glyph rectangles and UVs come from `core/labelLayout.ts`; each glyph's height is a per-instance attribute rewritten for dirty tiles, so labels ride their tile as it rises. The shader smooths the field's edge by its screen-space derivative and takes the scene's fog and tone mapping.
- `CameraRig.tsx`: the follow camera. Each frame it steps `core/camera.ts` with the controller's position and velocity and the ledge's height (`followHeight`), the focus held within `outerBounds(focusMargin, 0)`, and applies the pose and field of view. The character's frame callback has priority −1, so it runs first and the camera follows this frame's position. Zoom comes from the mouse wheel and a two-finger pinch on the canvas (the canvas sets `touch-action: none`) and from `+`/`-` on the window, ignored while a text field has focus. Under `prefers-reduced-motion` the establishing shot is skipped and a fly-to cuts the focus to its tile (`snapFocus`) instead of gliding. On narrow screens (the panel's `40rem` sheet breakpoint) it measures what covers the bottom of the canvas: the open panel sheet, from layout, and the lens box above it (or above the bottom edge), which grows as lenses turn on. It remeasures on panel, tile and size changes and through a `ResizeObserver` on the panel and the lens box, and shifts the image up by `sheetLift` with a projection view offset (`setViewOffset`), so the character sits in the visible part of the scene and tap picking still matches what is drawn; it clears the offset once the shift eases back to zero.
- `Character.tsx`: the procedural bean (capsule body, eyes, stub arms, two feet; 7 draw calls), starting on hydrogen. Sizes come from `CONFIG.character` at mount. Each frame it reads the held keys, merges in the joystick and any walk target with `steer`, steps the controller and the gait (fed the controller's real speed) and writes position, heading, lean and pose to refs. The controller, gait and input state belong to `Scene`, so a remount from the tuning panel keeps the character where it is. Its height comes from `core/ledge.ts` fed with `surfaceAt` and the tile top (`tileTop`, with its rise): it rides a rising tile, drops to the ground off an edge, hops back up onto a tile and squashes a little on landing (on top of the gait's own squash, keeping volume). Over a height lens landscape `blockCliffs` (`core/climb.ts`) stops it at a step up taller than `climbLimit`; a tap's walk target is dropped there, while one that may climb (`target.climb`) goes on and hops up. The walk cycle pauses while it is in the air. The ledge state belongs to `Scene` too, because `TileActivator` reads it.
- `FlightHandler.tsx`: carries out fly-to requests from the store: drops any walk target and teleports the controller (`teleport` in `core/controller.ts`) to the tile's centre at rest. The camera's spring follow then glides there. `Scene` also spawns the character on the deep-linked element, if the URL has one.
- `ReturnHandler.tsx`: carries out return requests (`returnSeq`) and walk requests (`walk`) from the store: sets the walk target to `lastTile`, or the nearest tile if there is none, as a walk that may climb cliffs (ADR 0014). The character walks back across the ground and hops up on arrival. Per request, outside the frame loop. Renders nothing.
- `TapToWalk.tsx`: click or tap to walk. A press on the canvas that stays short and still (and is not part of a pinch) is picks the first tile its ray meets at the drawn height, or the ground (`pickSurface`), and that point becomes the walk target, and places the tap marker. Work happens per tap, not per frame.
- `TapMarker.tsx`: draws the tap marker, a square outline just inside the target tile's top (a smaller one on the ground for a gap point). One mesh, visible only while the marker is live, so at most one extra draw call.
- `Joystick.tsx`: the on-screen joystick, a DOM element beside the canvas, shown only while a coarse pointer is present (`any-pointer: coarse`). Dragging the knob writes the deflection into a shared `Stick` that the character's frame reads; the knob moves by style, never React state. It recentres on release, blur or a hidden page, and is hidden from screen readers (the keyboard is the accessible way to walk). On wider touch screens it is a fixed pad in the bottom-left corner. On phones (a coarse pointer below the `40rem` sheet breakpoint) it floats: it listens to touches on the scene alongside tap-to-walk and the pinch, without capturing them, and appears centred where the thumb landed once a touch drifts past the tap threshold, so a still tap stays a walk tap and a second finger turns the gesture into a pinch. `TapToWalk` counts the farthest a press strayed, so a drag that comes back to its start is not a tap.
- `TileStepper.tsx`: I, J, K and L on the window set the walk target to the next tile with `stepTile`, and `[` / `]` to the previous or next element with `stepNumber`, starting from the tile already being walked to, else the tile underfoot, else the nearest one. These walks may climb cliffs (ADR 0014), so the keyboard reaches every tile under any lens. Per key press, outside the frame loop. Renders nothing.
- `useKeyboardInput.ts`: listens for key presses on the window and feeds them into one `InputState`. It ignores presses while a text field has focus or with ⌘/Ctrl/Alt held, prevents page scrolling for movement keys, and releases all keys when the window loses focus or is hidden.
- `useConfigVersion.ts`: re-renders on `CONFIG` changes and returns its version, used as a `key`.
- `PerfProbe.tsx`: with `?perf` in the URL, an overlay shows draw calls, triangles and mean and p95 frame time twice a second. The same numbers are on the overlay's `data-calls`, `data-mean` and `data-p95` attributes for scripts, with the pixel ratio on `data-dpr`.
- `QualityGovernor.tsx`: feeds each frame interval to `core/quality.ts` and calls R3F's `setDpr` only when the ratio changes. `?quality=off` pins it Frames after an idle wait are left out.
- `Suggestions.tsx`: combine mode's table guidance, lazily loaded with the orbs and the compound set, so the scene chunk carries no compound data. It renders nothing: when the carry or `open` changes it runs `suggestionWeights` and `suggestionDim` into the scene's suggestion `DimLayer`, which `Tiles.tsx` merges with the filters' dim. Inactive while Combine is closed or nothing is carried.
- `Orbs.tsx`: combine mode's carried atoms, lazily loaded the first time Combine opens. One instanced mesh of up to 24 spheres (one draw call while shown) in CPK colours from `compound-shapes.json` (only that table is imported, so the shapes stay out of the chunk), or the family colour for elements outside the compound set. The layout is rebuilt only when the carry changes; each frame the group follows the figure (`stepOrbFollow`) and repeats its walk bob (`CONFIG.combine.orbBob`; none with reduced motion). Hidden while Combine is closed or nothing is carried, and while the carry forms a compound.
- `Formed.tsx`: `FormedModel`, rendered inside the orbs' group so it rides with the figure: when the carry matches a compound (`useFormed`), the orbs spring from their slots into its ball-and-stick shape over the figure's head (atoms and sticks, two instanced meshes; shapes from `compound-shapes.json`'s `molecules` and `crystals` tables), then it turns slowly. Reduced motion fades it in and does not turn it. `FormArcs`: one line mesh in world space linking the compound's tiles in formula order, drawn along and then faded over `arcLife` seconds. Both tick and read the scene's `FormClock`; 14 draw calls in all while a compound and its arcs show.
- `FramePacer.tsx`: the canvas runs `frameloop="demand"`; this asks for every display frame while the figure, camera, tiles (activation, height lens, colour lens tint, temperature lens phase or discovery lens sink), carried orbs, a forming compound (until its animation and table arcs finish) or input move, and `CONFIG.pacing.idleFps` once all have been still for `settle` seconds (`core/pacer.ts`, [ADR 16](adr/0016-idle-frame-pacing.md)). Window input and app-store changes wake it.

## Element panel

`ui/ElementPanel.tsx` is lazily loaded by `App.tsx` and imports the element data directly; the bundler puts the data in a chunk shared with the scene, so the shell carries neither (ADR 0005). It reads `activeTile` from the store and slides in from the right (a bottom sheet below 40rem; a fade only under reduced motion) while the character stands on a tile, keeping the last element on screen as it slides out and making itself `inert` while closed. The header shows symbol, number, name, family and place in the table; three tabs (WAI-ARIA tabs: arrow keys, Home and End, which do not reach the movement keys) show `overviewFacts`, `propertyFacts` and the atom. The Atom tab draws `ui/AtomDiagram.tsx`, an inline SVG (`role="img"`, labelled by `atomSummary`) of the nucleus with the atomic number and one ring per shell with its electrons evenly spaced (`electronAngles`) around its count at the top, which they never cover; the outer ring takes the family accent. Below it come the stored configuration, the electrons per shell and, from `fillingNote`, a plain-words note when the element breaks the filling rule. The chosen tab stays as the player walks to other elements. Between the header and the tabs a short highlights list shows `rankFacts` and, once the player has seen another element, a "Compared with <that element>" line from `comparison`; the panel remembers the element it showed before, so walking, flying and returning all count. Its `--accent` and `--accent-ink` CSS variables come from `accentTokens`. With focus on the scene (or nowhere), Enter or Space opens the panel if it was closed and focuses it; Esc closes it for the current tile (`panelClosed`) and puts focus back on the scene.

## Key map

`ui/KeyHelp.tsx` is in the shell. `?` (outside text fields) or the Keys button opens a native modal `<dialog>` listing every key; `?`, Esc, the close button or a click on the backdrop closes it. Key events stop at the dialog. New keys go in its list (ADR 0008).

`ui/BackToTable.tsx` is in the shell too. R or Home (outside text fields, not on key repeat) calls `requestReturn`; a "Back to the table" button bottom centre does the same and shows once `offTable` has been true for two seconds. `TileStatus` reads "Off the table. Press R to return." while on the ground and carries `data-off` for tests.

`ui/CombineKeys.tsx` is in the shell as well, so the first C works before combine's chunk loads. C (outside text fields, not on key repeat) picks up one atom of the tile underfoot and opens Combine, or only opens it off the tiles; Backspace drops the last atom while Combine is open. The element panel's **Add to Combine** button does what C does. `ui/CombineTray.tsx` loads with combine's chunk (the compound set) the first time Combine opens, from a small slot in `App.tsx`, and then stays mounted, hidden while Combine is closed. It is a region titled Combine along the bottom centre (top right on narrow screens, clear of the element sheet and lenses; the return button moves to the top while it shows): the carried elements with − / + steppers (`dropOne`, `pickUp`; + on a full carry asks the store so the refusal is explained), **Clear**, a × close button, and the starters with **Show me** buttons (disabled until tours exist) when nothing is carried. A status region reads `traySummary`. Below it, while nothing forms and the carried elements are right but the amounts are not, the ratio line and a **Fill in** button (`fillIn`, `withCounts`); then the nearest three compounds (`nearest`, `nearMissLine`). Esc inside the tray closes it and returns focus to the table; when an edit removes the focused button (Clear, − on an element's last atom), focus moves to the close button. When the carry forms a compound (or a lone atom), its card (`ui/CompoundCard.tsx`) opens in the tray in place of the suggestions and the compound joins Recently made, kept in `localStorage` under `elemental:recent` (read and written in try/catch, so blocked storage only makes it last for the visit). A card opened that way closes when the carry stops matching; one opened from Recently made or a Leads to link takes focus and stays until closed. Esc closes the card first, then the tray. Starters' **Show me** runs `ui/useShowMe.ts`: it clears the carry, then for each stop from `core/tour.ts` calls `walkTo` or `flyTo`, waits on the store until `activeTile` is that tile (flying there after 8 s if a walk is stuck), and picks the atoms up one by one with short pauses. Compounds formed on the way (hydrogen gas before water) are not recorded. A key or pointer press outside the tray, Stop, Clear, a stepper or closing the tray ends the tour and keeps what was picked up. It runs on timers and store subscriptions, never in frame code.

## Explorer

`ui/Explorer.tsx` is lazily loaded like the panel and shares its data chunk. A button under the title, `⌘K`/`Ctrl K` or `/` (outside text fields) opens a native modal `<dialog>`: a search box (a WAI-ARIA combobox whose arrow keys, Page Up/Down and Enter drive a listbox of results), a sort select with a direction toggle, and filters for family, state, block, period and group. Each result shows the family accent, the name, the sorted value and the atomic number. Choosing one closes the palette and calls `flyTo`. The filters also go to the store (`setLensFilters`), so the table dims every tile they exclude, with the palette open or closed, and the Explore button shows "Filtered" until they are cleared. Key events stop at the dialog, so typing never walks or zooms the scene; on close, focus returns to where it was, or leaves the hidden search box.

The same module keeps the address on the element under the character and the lenses (`#/Au?lens=density&colour=meltingPoint`, with `history.replaceState`; off the table it keeps the element already named) and flies to an element and sets the lens when the hash is edited, rewriting hand-typed forms to the canonical symbol.

`ui/LensControl.tsx`, lazily loaded (it needs only the lens core), is the lenses' HUD control under the List button, a small "Lenses" landmark: a Height select (Flat or a property) and a Colour select (Family or a property), and the H and G keys (Shift backward, outside text fields) that cycle each lens and announce the choice through a status region. While a colour lens is on it shows `ui/ColourLegend.tsx`, loaded on demand in the data chunk: a figure captioned with the property, a decorative gradient bar of `COLOUR_RAMP` (blended in linear light where CSS supports `in srgb-linear`), the lowest and highest values as text, "log scale" when it applies and a no-data swatch with its count (`lensLegend`). On narrow screens the control runs along the bottom, just above the element sheet while it is open (`:has(.panel[data-open='true'])`), so it never covers the figure. With a lens on, `ui/ElementList.tsx` adds a column with each element's value.

Below them, `ui/TemperatureControl.tsx` is the temperature lens's row, built on `ui/ScrubLens.tsx`, the shared control for lenses set by a value on a scale. `ScrubLens` takes the lens's label, key, value and setter, its scale (`positionOf`, and `valueAt(p, snap)`), a formatter and detents, and draws a checkbox (or the key, outside text fields or on the row's own controls) that turns the lens on at the last value and focuses the slider, or off; while on, an `input type=range` of 1,000 steps (`aria-valuetext` with the detent's name), tick marks and toggle buttons for the detents, the value as an `<output>`, and its children. Pointer drags snap to detents; keyboard steps do not, since a step is smaller than the snap window. Esc on the slider returns focus to the table. `LiveSummary` shows a summary at once and repeats it in a polite live region 600 ms after the last change, so a drag is announced once. The temperature row (key T, `sliderKelvin`, `formatTemperature`, presets Room, Body, Water boils) puts `ui/TemperatureSummary.tsx` under it, in the data chunk, with the counts per state. On narrow screens a scrub row packs into three lines (toggle and slider, value and presets, summary). The element panel's overview adds `phaseFact` after the state at room temperature while the temperature lens is on.

`ui/DiscoveryControl.tsx` is the discovery lens's row under it, on the same `ScrubLens` (key Y, `positionOfYear`, `sliderYear`, `yearLabel`, presets from `YEAR_DETENTS`; it turns on at 1869 the first time). A detent may carry a `short` label: phones show it on the button and keep the full label as its accessible name ("Mendeleev" for "Mendeleev's table"). `ui/DiscoverySummary.tsx`, in the data chunk, shows the counts (`discoverySummary`) and the latest year with a discovery up to the chosen one (`latestDiscoveries`, hidden on phones), and speaks the counts 600 ms after the last change, with `discoveryNews` since the last time it spoke ("Discovered: Ra, Po, Xe, Kr, Ne"). Two toggle rows are at least 24 px tall, so the stacked checkboxes meet the minimum target spacing. A Play button beside the counts sweeps the year to today: along the slider's track in `PLAY_SECONDS` (20 s for the whole track, so the dense 19th century gets most of the time) from `playStart`, writing the store only when the whole year changes, or under reduced motion a decade (`nextDecade`) every `PLAY_STEP_SECONDS`. The row's setter pauses it, so the slider, a preset, the switch and Y all do; the lens turning off stops it. It announces its start, pause and end through the lens control's status region, and the summary stays quiet while it plays (`quiet`), catching up with the year so nothing is spoken when it stops. The element panel's overview adds `eraFact` after the discovery year while the lens is on ("In 1869: Not yet discovered").

## Element list

`ui/ElementList.tsx` is the non-3D way through the table, lazily loaded in the same data chunk as the panel and explorer. The List button under Keys opens a native modal `<dialog>` with an HTML `<table>` of every element in atomic-number order (number, symbol, name as a row header, family, period, group); the row the character stands on carries `aria-current="location"`. Each name is a button that closes the list and calls `flyTo`. Key events stop at the dialog.

## Focus and tab order

DOM order in `App.tsx` is the tab order: title, Explore, Keys and List come first, then the focusable scene, then the element panel. While any modal dialog is open, the panel's Enter, Space and Esc handling stands aside, so Esc always closes the dialog, even if focus has fallen to the page body.

## Tuning panel

With `?tune` in the URL, the dev server shows a [leva](https://github.com/pmndrs/leva) panel with a slider per `CONFIG` value (`src/ui/TunePanel.tsx`). It writes through `setConfig`, so the scene changes live. "Copy as defaults" puts the current values on the clipboard as JSON to paste into `config.ts`; "reset" restores the defaults. The panel is loaded with a dynamic import guarded by `import.meta.env.DEV`, so a production build contains neither the panel nor leva, and `?tune` does nothing there.

## Testing

- Unit tests (`*.test.ts` next to the code) cover `src/core`. The normalizer is tested against small recorded responses in `src/core/elements/__fixtures__/`; another test validates the whole committed dataset. The compound tests rebuild `compounds.json` and `compound-shapes.json` from the PubChem rows the script saved in `src/core/compounds/__fixtures__/` and checks it matches.
- `scripts/three-catalogue.ts` points React Three Fiber's `three` import at `src/scene/threeCatalogue.ts` in the production build, so three is tree-shaken (ADR 0012). `scripts/three-catalogue.test.ts` checks the catalogue holds every class a JSX element names and every name R3F reads; add a class there when the scene uses a new lowercase JSX element.
- `scripts/size-check.mjs` builds the app and fails `npm run check` if the gzipped JavaScript passes either ceiling: 76 KB for the shell (the entry chunk and its static imports, read from the Vite manifest) and 324 KB for all chunks together (raised for combine mode, ADR 0003 amendments).
- `npm run perf` runs `e2e/perf/perf.spec.ts` with `playwright.perf.config.ts` (the smoke run ignores `e2e/perf`): time to first move and frame work, see [performance](performance.md).
