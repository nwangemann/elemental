# Architecture

## Layers

- `src/core`: pure TypeScript. Maths, layout, data shaping, rules. No React, no three, no DOM, so everything here is unit-tested in Node.
- `src/scene`: React Three Fiber components (see [ADR 2](adr/0002-scene-rendering.md)). Per-frame work happens in `useFrame` and mutates refs; it never sets React state.
- `src/state`: the app store (zustand, [ADR 4](adr/0004-app-state.md)), shared by the scene and the DOM interface. `activeTile` is the tile under the character (number and name), or null; the scene writes it only when that changes. `flight` is the latest fly-to request (`flyTo(number)`), from the explorer or a deep link. `panelClosed` is true while the player has closed the panel with Esc on the current tile; entering another tile resets it. `lastTile` is the last tile stood on (kept while off the table) and `offTable` is true while the character is on the ground (ADR 0009); both change only on change. `returnSeq` counts return requests (`requestReturn()`).
- `src/ui`: DOM interface. The element panel (`ElementPanel.tsx`), a screen-reader status that announces the tile under the character (`TileStatus.tsx`, "Standing on Hydrogen"), the explorer (`Explorer.tsx`), the key map overlay (`KeyHelp.tsx`), the plain-text element list (`ElementList.tsx`), the return key and button (`BackToTable.tsx`) and the dev-only tuning panel.
- `src/data`: generated element data (`elements.json`), committed. Built by `scripts/build-elements.ts`; see [data sources](data-sources.md).

## Core modules

- `damp.ts`: frame-rate independent smoothing. `damp` is first-order exponential smoothing (movement, zoom); `stepSpring` is an exact critically damped spring with velocity, which eases in and out and never overshoots a still target (camera follow).
- `camera.ts`: the third-person camera as pure maths. A focus point follows the character on two springs, aimed `lookAhead` seconds along its velocity so the view leads the walk. That aim is clamped to bounds the rig passes in (the table's footprint plus `focusMargin`), so the view stops at the table's edge while the character walks on into the margin and the table stays in frame. The camera sits behind and above the focus at `pitch` and a zoom distance that eases toward a target, clamped between `minDistance` and `maxDistance`; zoom works in log steps (`zoomBy`, one key press or 100 px of wheel) or by a pinch factor (`zoomByFactor`). Its heading is fixed (looking toward −z), so keyboard directions stay screen-relative. The establishing shot holds the overview pose (`CONFIG.camera.position` and `target`) for `introDelay`, then blends into the follow pose over `introDuration` with a smootherstep curve; `skipIntro` ends it at once.
- `elements/categories.ts`: the fixed value lists (the ten families that drive tile colours and themes, states, blocks), free of zod so the app can import them.
- `elements/schema.ts`: the zod schema and the `Element` type. Only the data script and tests run it; the app imports its types, so zod is not in the app bundle.
- `elements/position.ts`: period, group and block from the atomic number.
- `elements/normalize.ts`: turns PubChem's table and Wikidata's SPARQL rows into validated elements. Used by the build script and its tests.
- `elements/index.ts`: `ELEMENTS`, the committed dataset, and lookups. This is what the app imports.
- `layout.ts`: where each tile sits. An 18 × 10 grid (groups as columns, periods as rows; the two f-block rows sit under groups 3–16 after one empty row), centred on the origin of the x–z ground plane. Converts world ↔ grid and finds the tile under a point in O(1) without allocating. The lookup takes the current tile for hysteresis: a tile is kept until the character is `LAYOUT.hysteresis` past its edge, which is wider than the gap, so walking along a boundary does not flicker. Tile size, gap and margin live in `LAYOUT`.

- `config.ts`: visual and feel parameters (tile height, resting material and theme strength, label sizes, camera). `CONFIG_DEFAULTS` holds the shipped values and `CONFIG_RANGES` the slider bounds. The app reads `CONFIG`, a mutable copy; `setConfig` changes one value, bumps a version and notifies subscribers. Per-frame code reads `CONFIG` every frame and needs no subscription. Objects built once from it (tile geometry, the label batch) are remounted by `Scene` when the version changes.
- `gait.ts`: the character's procedural motion. `stepGait` advances time, the walk phase (one cycle per `strideLength` travelled, so feet do not slide at any speed) and a walk blend that follows speed; `poseOf` turns that into body bob, squash and stretch (volume kept), foot swing and lift, and arm swing, written into a reused object. Idle breathing fades out as the walk fades in.
- `input.ts`: keyboard movement as data. `KEY_MAP` maps `KeyboardEvent.code` (physical keys, so WASD works on any layout) to actions: WASD and the arrows both move, either Shift walks slowly. `applyKey` records presses into a set of held codes, and `moveIntent` turns them into a normalised x–z direction (a `MoveIntent` may be shorter than 1, from the joystick or a slowing approach, and its length scales speed) (forward is −z, away from the camera; opposite keys cancel). `ZOOM_KEYS` maps the typed `+`/`=` to zoom in and `-`/`_` to zoom out; these go by `KeyboardEvent.key`, since the characters sit on different physical keys across layouts.
- `steering.ts`: pointer and touch movement. `setWalkTarget` turns a point on the table into a walk target, snapped to the centre of the tile under it (or kept as is over a gap). `stickFromOffset` maps the joystick knob's screen offset to an analog x–z vector (screen up is −z, matching the fixed camera; a dead zone, then linear to full at `stickRadius`). `steer` merges the sources into the frame's `MoveIntent`: held keys win and cancel any walk target, then a deflected joystick, then the target, steered toward in a straight line and slowed linearly inside `slowRadius` until it is reached at `arriveRadius`. `isTap` tells a tap or click (short and still) from a drag. Parameters live in `CONFIG.character`.
- `tapMarker.ts`: the marker a tap leaves on its walk target. `placeTapMarker` starts it on the target just set (tile index, or −1 for a gap or ground point); `stepTapMarker` ages it and ends it once that target is no longer the active one (arrival, keys, joystick, a step key, another tap, a fly-to); `tapMarkerLook` gives the pulse: from 1.6× size and full opacity, eased over `markerPulse` seconds to rest size and `markerOpacity` (size fixed under reduced motion). Parameters live in `CONFIG.tiles`.
- `controller.ts`: the kinematic character controller. `stepController` eases velocity toward the intent with `damp` (separate rates for accelerating and stopping), softens the edge of its bounds (in a band `edgeBand` wide inside each limit the outward speed allowed falls to zero and a push of up to `edgePush` eases the body back inside), integrates position, clamps it to the bounds as a guarantee and zeroes velocity against them, turns the heading toward the travel direction the short way round, and leans into turns in proportion to turn rate × speed, capped. Allocation-free; parameters live in `CONFIG.character`.
- `palette.ts`: the family colours, label ink, ground and sky, the character's body and eyes, the panel's surface and text, and WCAG contrast helpers. Tests check AA contrast for label ink on every family colour, that the ground stands off the sky (at least 1.4:1) and that every family colour stands out on the ground (at least 3:1).
- `themes.ts`: each element family's look as data (ADR 0006). A `Theme` holds the tile's base colour (from `palette.ts`), the `awake` surface it wakes into (roughness, metalness, glow strength and colour, and how deeply the glow pulses) and the interface's accent tokens. `accentTokens(category)` gives the DOM panel its accent and the ink for text on it, so the panel and the tile come from one entry. `surfaceAt` blends a tile's surface from a shared resting look (`CONFIG.tiles.roughness`/`metalness`, leaning `restMix` toward the family) to the awake look by activation level, writing into an instance buffer without allocating. Tests check every family has a theme, values stay in range, and accents keep AA contrast on the panel.
- `activation.ts`: which tile the character stands on and how far each tile is through entering or leaving. `stepActivation` finds the current tile with `tileAtPoint` (with hysteresis); given `standingOn` from `ledge.ts`, there is no current tile unless the character stands on a tile top, and just past a tile's edge the supporting tile counts. It ramps it linearly toward 1 and every other tile toward 0 over `CONFIG.tiles.activateDuration` (0.25 s), and reports whether the current tile changed. A `dirty` flag per tile (and `anyDirty`) tells renderers which tiles moved this frame. `easeLevel` is the smoothstep the renderers apply; `tileTop` is a tile's top height with its eased rise. Allocation-free.
- `explorer.ts`: the explorer's logic (ADR 0007). `explore` filters elements by family, state, block, period and group, matches a query in tiers (exact number, symbol or name; prefix; contains; then letters in order, from three letters) and orders each tier by the chosen sort (atomic number, name, mass, discovery year with antiquity first, density, electronegativity, melting point), either direction, unknowns last. `sortValueLabel` formats the sorted value with its unit. `deepLink` and `parseDeepLink` write and read `#/Au` (also accepting `#/au`, `#/79` and `#/gold`).
- `tileStep.ts`: keyboard stepping from tile to tile (ADR 0008). `STEP_KEYS` maps I, J, K and L (by code) to up, left, down and right. `stepTile` finds the next tile in a direction, skipping gaps and empty cells, through the gap row into and out of the f-block, and to the nearest tile of the next row when a column runs out; null at the edge. `nearestTile` gives a starting tile when the character stands between tiles. `RETURN_KEYS` (R and Home, by code) and `isReturnCode` are the keys that walk back to the table.
- `boundary.ts`: what the character stands on (ADR 0009). Tiles are low platforms on open ground. `surfaceAt` gives the atomic number of the tile supporting a body centred at a point, or `GROUND` (0): a tile supports the centre up to `BOUNDARY.support` (0.1) past its edge, which bridges the 0.15 gaps between neighbours, so only real empty space (the d-block notch, the gap row, the corners beside the f-block, the margin outside) is ground. O(1), allocation-free. `groundHeightAt` is the resting height there (tile height or 0). `outerBounds` is the walkable area for a body: the table's footprint plus `BOUNDARY.margin` (1.5) of ground on every side. The character's height uses `surfaceAt`, and the controller is bounded by `outerBounds`, so the figure can walk off any edge onto the ground and out to the margin's soft limit.
- `ledge.ts`: the character's height and the moves between tiles and ground (ADR 0009). Standing, the feet follow the surface with `damp` (`standRate`), so a rising tile is ridden and stepping between a raised and a resting tile dips gently. Leaving a tile for the ground starts a fall under `gravity`; moving from the ground onto a tile (walking, a walk target or a fly-to) starts a hop: a straight rise plus a parabolic arc of `hopHeight` over `hopDuration`, ending on the tile top. A hop that moves back over the ground turns into a fall, and a fall that reaches a tile turns into a hop. Landing sets a body squash (`landSquash`) that recovers at `squashRecover`. `standingOn` is the tile under the feet only while standing on top, `GROUND` otherwise; `isAirborne` is true while falling or hopping. Parameters live in `CONFIG.character`; allocation-free.
- `elementFacts.ts`: the element panel's text. `overviewFacts` and `propertyFacts` turn an element into labelled rows with units (temperatures in K with °C alongside, gas densities in g/L, signed oxidation states, superscript electron counts); missing values read "Unknown" and predicted ones carry a note. `CATEGORY_LABELS` names the families.
- `frame-stats.ts`: rolling mean and percentile of frame times, allocation-free on push.
- `quality.ts`: adaptive resolution (ADR 0010). `stepQuality` averages frame intervals over one-second windows after a warm-up and steps the pixel ratio by 0.25 between `minDpr` 0.75 and the display's own ratio (capped at 2): down below about 45 fps, up above about 57 fps. Intervals over 250 ms are pauses. After three changes of direction it settles on the lower ratio. Returns true only when the ratio changes; allocation-free.

## Scene

`App.tsx` loads the scene with `React.lazy`, so three, React Three Fiber, troika and the element data arrive as a separate chunk after the DOM shell has painted; a "Loading the table…" status shows meanwhile (ADR 0003).

- `Scene.tsx`: the canvas (its wrapper is the scene's one focus stop: `role="application"`, a label naming the keys, the tile status as its description, a focus ring), background and fog, a hemisphere and a directional light, and the ground: a low plinth (one box mesh) covering exactly the walkable area, the table plus `BOUNDARY.margin`, so the outer limit shows as the plinth's edge with the sky beyond. The ground colour is lighter than the sky so the area reads as ground, not void.
- `TileActivator.tsx`: steps `core/activation.ts` with the character's position each frame, after the character moves (priority −0.5) and before anything draws, and writes `activeTile` to the store only when the tile changes. It passes `standingOn` from the character's ledge state, so a tile wakes only once the character is on top of it: not while it hops up, and not after it drops to the ground beside it. It also writes `offTable` (standing on `GROUND`, including mid-fall or mid-hop) when that changes. Renders nothing.
- `Tiles.tsx`: all 118 tiles as one `InstancedMesh` (one draw call), positioned from `TILES`, coloured from each family's theme, and given its surface per instance with `surfaceAt`, so a tile's material fades into its family's awake look as it activates. An active tile rises by `CONFIG.tiles.rise`, stretching up from the ground so no gap opens beneath it; only tiles marked dirty are rewritten. Metals reflect a procedural studio environment (three's `RoomEnvironment`, prefiltered once at mount; nothing is downloaded), set on this material only.
- `tileMaterial.ts`: the tiles' material, a `MeshStandardMaterial` patched in `onBeforeCompile` to read roughness, metalness and glow from per-instance attributes (`aSurface`, `aGlowColor`) and to breathe the glow over time. The environment adds reflections only (its diffuse light is dropped), so family colours keep their tone. Glow scale, pulse rate and reflection strength are live `CONFIG.tiles` values.
- `TileRings.tsx`: a square highlight ring on the ground around each active tile, one `InstancedMesh` (one draw call). It grows out from under the tile as the tile activates and shrinks back as it leaves; at rest it is scaled to zero, so the mesh is not frustum-culled.
- `Labels.tsx`: each tile's symbol and atomic number as troika SDF text, merged into one `BatchedText`. Labels ride their tile as it rises; `BatchedText` reads member matrices every frame, so moving a label needs no re-sync. Glyphs are built in troika's workers (`gpuAccelerateSDF = false`) so the first frame does not wait for them, and the production build drops troika's GPU warm-up (`scripts/troika-no-sdf-warmup.ts`, ADR 0010).
- `CameraRig.tsx`: the follow camera. Each frame it steps `core/camera.ts` with the controller's position and velocity, the focus held within `outerBounds(focusMargin, 0)`, and applies the pose and field of view. The character's frame callback has priority −1, so it runs first and the camera follows this frame's position. Zoom comes from the mouse wheel and a two-finger pinch on the canvas (the canvas sets `touch-action: none`) and from `+`/`-` on the window, ignored while a text field has focus. Under `prefers-reduced-motion` the establishing shot is skipped and a fly-to cuts the focus to its tile (`snapFocus`) instead of gliding.
- `Character.tsx`: the procedural bean (capsule body, eyes, stub arms, two feet; 7 draw calls), starting on hydrogen. Sizes come from `CONFIG.character` at mount. Each frame it reads the held keys, merges in the joystick and any walk target with `steer`, steps the controller and the gait (fed the controller's real speed) and writes position, heading, lean and pose to refs. The controller and input state belong to `Scene`, so a remount from the tuning panel keeps the character where it is. Its height comes from `core/ledge.ts` fed with `surfaceAt` and the tile top (`tileTop`, with its rise): it rides a rising tile, drops to the ground off an edge, hops back up onto a tile and squashes a little on landing (on top of the gait's own squash, keeping volume). The walk cycle pauses while it is in the air. The ledge state belongs to `Scene` too, because `TileActivator` reads it.
- `FlightHandler.tsx`: carries out fly-to requests from the store: drops any walk target and teleports the controller (`teleport` in `core/controller.ts`) to the tile's centre at rest. The camera's spring follow then glides there. `Scene` also spawns the character on the deep-linked element, if the URL has one.
- `ReturnHandler.tsx`: carries out return requests from the store (`returnSeq`): sets the walk target to `lastTile`, or the nearest tile if there is none. The character walks back across the ground and hops up on arrival. Per request, outside the frame loop. Renders nothing.
- `TapToWalk.tsx`: click or tap to walk. A press on the canvas that stays short and still (and is not part of a pinch) is projected onto the plane of the tile tops and becomes the walk target, and places the tap marker. Work happens per tap, not per frame.
- `TapMarker.tsx`: draws the tap marker, a square outline just inside the target tile's top (a smaller one on the ground for a gap point). One mesh, visible only while the marker is live, so at most one extra draw call.
- `Joystick.tsx`: the on-screen joystick, a DOM element beside the canvas, shown only while a coarse pointer is present (`any-pointer: coarse`). Dragging the knob writes the deflection into a shared `Stick` that the character's frame reads; the knob moves by style, never React state. It recentres on release, blur or a hidden page, and is hidden from screen readers (the keyboard is the accessible way to walk). On narrow screens it sits above the panel sheet.
- `TileStepper.tsx`: I, J, K and L on the window set the walk target to the next tile with `stepTile`, starting from the tile already being walked to, else the tile underfoot, else the nearest one. Per key press, outside the frame loop. Renders nothing.
- `useKeyboardInput.ts`: listens for key presses on the window and feeds them into one `InputState`. It ignores presses while a text field has focus or with ⌘/Ctrl/Alt held, prevents page scrolling for movement keys, and releases all keys when the window loses focus or is hidden.
- `useConfigVersion.ts`: re-renders on `CONFIG` changes and returns its version, used as a `key`.
- `PerfProbe.tsx`: with `?perf` in the URL, an overlay shows draw calls, triangles and mean and p95 frame time twice a second. The same numbers are on the overlay's `data-calls`, `data-mean` and `data-p95` attributes for scripts, with the pixel ratio on `data-dpr`.
- `QualityGovernor.tsx`: feeds each frame interval to `core/quality.ts` and calls R3F's `setDpr` only when the ratio changes. `?quality=off` pins it.

## Element panel

`ui/ElementPanel.tsx` is lazily loaded by `App.tsx` and imports the element data directly; the bundler puts the data in a chunk shared with the scene, so the shell carries neither (ADR 0005). It reads `activeTile` from the store and slides in from the right (a bottom sheet below 40rem; a fade only under reduced motion) while the character stands on a tile, keeping the last element on screen as it slides out and making itself `inert` while closed. The header shows symbol, number, name, family and place in the table; two tabs (WAI-ARIA tabs: arrow keys, Home and End, which do not reach the movement keys) show `overviewFacts` and `propertyFacts`. Its `--accent` and `--accent-ink` CSS variables come from `accentTokens`. With focus on the scene (or nowhere), Enter or Space opens the panel if it was closed and focuses it; Esc closes it for the current tile (`panelClosed`) and puts focus back on the scene.

## Key map

`ui/KeyHelp.tsx` is in the shell. `?` (outside text fields) or the Keys button opens a native modal `<dialog>` listing every key; `?`, Esc, the close button or a click on the backdrop closes it. Key events stop at the dialog. New keys go in its list (ADR 0008).

`ui/BackToTable.tsx` is in the shell too. R or Home (outside text fields, not on key repeat) calls `requestReturn`; a "Back to the table" button bottom centre does the same and shows once `offTable` has been true for two seconds. `TileStatus` reads "Off the table. Press R to return." while on the ground and carries `data-off` for tests.

## Explorer

`ui/Explorer.tsx` is lazily loaded like the panel and shares its data chunk. A button under the title, `⌘K`/`Ctrl K` or `/` (outside text fields) opens a native modal `<dialog>`: a search box (a WAI-ARIA combobox whose arrow keys, Page Up/Down and Enter drive a listbox of results), a sort select with a direction toggle, and filters for family, state, block, period and group. Each result shows the family accent, the name, the sorted value and the atomic number. Choosing one closes the palette and calls `flyTo`. Key events stop at the dialog, so typing never walks or zooms the scene; on close, focus returns to where it was, or leaves the hidden search box.

The same module keeps the address on the element under the character (`#/Au`, with `history.replaceState`) and flies to an element when the hash is edited, rewriting hand-typed forms to the canonical symbol.

## Element list

`ui/ElementList.tsx` is the non-3D way through the table, lazily loaded in the same data chunk as the panel and explorer. The List button under Keys opens a native modal `<dialog>` with an HTML `<table>` of every element in atomic-number order (number, symbol, name as a row header, family, period, group); the row the character stands on carries `aria-current="location"`. Each name is a button that closes the list and calls `flyTo`. Key events stop at the dialog.

## Focus and tab order

DOM order in `App.tsx` is the tab order: title, Explore, Keys and List come first, then the focusable scene, then the element panel. While any modal dialog is open, the panel's Enter, Space and Esc handling stands aside, so Esc always closes the dialog, even if focus has fallen to the page body.

## Tuning panel

With `?tune` in the URL, the dev server shows a [leva](https://github.com/pmndrs/leva) panel with a slider per `CONFIG` value (`src/ui/TunePanel.tsx`). It writes through `setConfig`, so the scene changes live. "Copy as defaults" puts the current values on the clipboard as JSON to paste into `config.ts`; "reset" restores the defaults. The panel is loaded with a dynamic import guarded by `import.meta.env.DEV`, so a production build contains neither the panel nor leva, and `?tune` does nothing there.

## Testing

- Unit tests (`*.test.ts` next to the code) cover `src/core`. The normalizer is tested against small recorded responses in `src/core/elements/__fixtures__/`; another test validates the whole committed dataset.
- `scripts/size-check.mjs` builds the app and fails `npm run check` if the gzipped JavaScript passes either ceiling: 80 KB for the shell (the entry chunk and its static imports, read from the Vite manifest) and 380 KB for all chunks together.
- `npm run perf` runs `e2e/perf/perf.spec.ts` with `playwright.perf.config.ts` (the smoke run ignores `e2e/perf`): time to first move and frame work, see [performance](performance.md).
- `e2e/smoke.spec.ts` builds the app, serves it with `vite preview` and checks in Chromium that it loads, that the panel shows hydrogen, where the character starts, with its properties tab, that clicking a tile walks there, that a deep link starts on its element, and that the explorer finds neon and flies there, and that the keyboard alone tabs to the scene, steps H → Li → Be → B → C, closes and reopens the panel with Esc and Enter, moves through its tabs and opens the key map.
- `e2e/a11y.spec.ts` runs axe (WCAG 2.2 A/AA and best practice) on the hydrogen and gold panels, the explorer, the key map and the element list, and checks that Tab runs Explore → Keys → List → scene → panel and that the list has all 118 rows and walks to gold. axe cannot judge text drawn over the canvas, so `e2e/contrast.ts` also screenshots the scene with the interface hidden, composites each text element's backgrounds over the lightest and darkest scene pixel behind it and fails below 4.5:1 (3:1 for large text).
